# บันทึกประวัติ V12 ก่อนอนุมัติ (ไม่ใช่สถานะปัจจุบัน)

เป้าหมายเดียว: `etcstream-online` / `abtzrovcsomghbuwdmrr` / Tokyo

ไฟล์ `migrations/20261020125254_real_online_v12.sql` เป็นข้อเสนอ ยังไม่ได้รันในฐานข้อมูลจริง
ปลั๊กอินที่แชตนี้ใช้ตอบว่าไม่มีสิทธิ์เข้าโครงการเป้าหมาย จึงยังตรวจ schema และ Auth จริงไม่ได้
ก่อนรันต้องตรวจตารางเดิมและชื่อ object ให้ครบ หากชนกันให้สร้าง corrective migration เพิ่ม ห้ามแก้ migration ที่ deploy แล้ว

ผลกระทบ: สร้างตาราง `etc_*`, schema ภายใน, RPC และ policy ช่อง Realtime ใหม่ ไม่ลบ/นำเข้าข้อมูลเก่า
ไม่มีการ import คะแนนจาก localStorage/SQLite ไม่มีการสร้างผู้เล่นหรือผลแข่งขันตัวอย่าง
เปิด RLS ทุกตารางสาธารณะที่เพิ่ม และถอนสิทธิ์เขียนตรงของผู้เล่น ใช้ RPC ตรวจ auth.uid() สำหรับข้อมูลผู้เล่น
การบันทึกเกมและการดูแลผู้เล่นใช้ service key เฉพาะเซิร์ฟเวอร์ หลังตรวจผู้เล่น/เซสชันเจ้าของ

ก่อนอนุมัติ: สำรองฐานข้อมูลจริงด้วยเครื่องมือ Supabase, ตรวจ SQL ทุกบรรทัด และตรวจนโยบาย realtime.messages เดิม
หลังอนุมัติ: ใช้ Supabase migration tooling กับโครงการที่ยืนยันแล้วเท่านั้น แล้วตรวจ advisors และ grants/policies
อย่ารัน SQL นี้ด้วยบัญชีของอีกโครงการเพื่อทดลอง

Rollback: ปิด `ARENA_BACKEND` และหยุดรับผู้เล่นออนไลน์ก่อน คืนโค้ดเป็นรุ่นก่อนหน้าแบบไม่ลบข้อมูล
หากมีข้อมูลจริงแล้ว ให้ทำ corrective migration พร้อมแผนสำรองและเจ้าของอนุมัติ ห้าม drop ตารางเพื่อย้อนกลับ

ข้อจำกัด: ไม่มีฤดูกาลหรือ duel ใน cloud schema นี้ ทุกผลจบอยู่ UNDER_REVIEW/REJECTED/DNF เท่านั้น
ต้องพัฒนา eligibility ของทั้ง 25 ด่าน การ replay ตรวจอิสระตอนจบ และฤดูกาลก่อนเปิดอันดับจริง
คำสั่งสูงสุด 5,000 ต่อรอบ และรอบหมดอายุ 4 ชั่วโมง จำกัดรอบเริ่ม 8 ต่อชั่วโมงต่อบัญชี
ต้องกำหนดนโยบายเก็บ command ledger และผู้เล่นไม่ใช้อีเมลก่อนเปิดวงกว้าง; ไม่มีการลบอัตโนมัติใน migration นี้
