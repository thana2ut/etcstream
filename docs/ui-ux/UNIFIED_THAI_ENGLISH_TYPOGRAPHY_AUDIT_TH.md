# รายงานระบบตัวอักษรไทย–อังกฤษและป้ายภายในห้อง

วันที่ 20 ตุลาคม 2026 — งานรอบนี้ตรวจและแก้จากซอร์สเท่านั้น ไม่เปิด/ควบคุม Chrome และไม่มีภาพหรือผลเล่นจริงใหม่

## สาเหตุที่ยืนยันได้

ข้อความสามมิติใช้ไฟล์ scene-thai-latin.ttf ซึ่งผสมโครงตัวไทย Kart กับตัวละติน Geist ส่วนหน้าต่าง HTML ใช้ Sarabun และหัวข้อประดับบางจุดใช้ฟอนต์พู่กัน จึงมีรูปทรงและสัดส่วนต่างกันแม้ชื่ออุปกรณ์อยู่ใกล้กัน ป้าย GenericLabel กับ DeviceLabel ใช้ขนาด ช่องว่าง และเส้นขอบคนละค่า ข้อความรองเดิมยึดขอบบนแล้วขยายลงใกล้ตัวอุปกรณ์ และตัวแสดง Text แต่ละจุดกำหนดระยะบรรทัดไม่เหมือนกัน

ตัวอย่าง Computer (OBS) มาจาก label อุปกรณ์ studio-full ผ่าน DeviceVisual/GenericDevice ไม่จำเป็นต้องแก้ข้อมูลฮาร์ดแวร์หรือชื่อรุ่น HP การนำเสนอเปลี่ยนเป็น “คอมพิวเตอร์ (OBS)” ผ่านพจนานุกรมแสดงผลเท่านั้น ข้อความ HP 15.6-inch (ตามงานอ้างอิง) คงเดิม

**ป้ายบิดเบี้ยวในภาพเพิ่มเติม:** รอบนี้มีเอกสารบรรยายแต่ไม่มีภาพใหม่ที่ชี้ตำแหน่งได้แน่ชัด จึงยังระบุไม่ได้ว่าเป็นป้ายใดหรือสาเหตุภาพจริงเกิดจากฟอนต์ มุมมอง หรือการยืดพื้นผิว ไม่เดาคำบนป้าย การแก้ renderer ร่วมครอบคลุมป้ายที่สร้างจาก Text และ Canvas ตามที่ตรวจพบ แต่ไม่อ้างว่าแก้ป้ายในภาพนั้นได้ตรงจุดจนกว่าจะตรวจภาพจริง

## ฟอนต์และสิทธิ์ใช้

ใช้ Sarabun Regular ครอบคลุมไทยและละตินในไฟล์เดียวสำหรับสามมิติและ Canvas สอดคล้องกับ Sarabun ที่ HTML ของโครงการใช้อยู่ รวบรวมจากไฟล์ย่อย Sarabun น้ำหนัก 400 จำนวนสี่ไฟล์ที่ next/font โหลดไว้แล้วใน .next/static/media ไม่ดาวน์โหลดตระกูลฟอนต์ใหม่

สร้าง `public/fonts/scene-sarabun.ttf` (640 รายการรหัสอักขระ) พร้อม `public/fonts/scene-sarabun.txt` บันทึกที่มา/การสร้าง เก็บไฟล์ Kart, Geist และฟอนต์ผสมเก่าไว้ ไม่แทนที่ไฟล์ต้นฉบับ ฟอนต์มีข้อมูลสิทธิ์ SIL Open Font License ตามลิงก์ใน metadata ของต้นฉบับ ใช้เครื่องมือ FontTools/Brotli ชั่วคราวนอก repository เพื่อรวม subset ไม่มี dependency ใหม่ใน package.json

ฟอนต์เก็บตาราง cmap/GSUB/GPOS และ metrics เดิม ตรวจตัวอย่างไทย/อังกฤษแล้วมีอักขระครบ ascent 1068 / descent -232 / หน่วยต่อ em 1000 ไม่จัดตำแหน่งสระหรือวรรณยุกต์ทีละตัว

## การเปลี่ยนส่วนร่วม

- `game/rendering/scene-font.ts`: เปลี่ยน SCENE_FONT และ FontFace เป็น Sarabun ไฟล์เดียว ใช้ stack สำรอง Leelawadee UI / Tahoma เมื่อจำเป็น เพิ่ม SCENE_TYPE สำหรับชื่ออุปกรณ์ ข้อความรอง พอร์ต สถานะ คำสั่ง จอ แผนผัง และคำอธิบาย ระยะบรรทัด 1.65–1.7 การแปลงสัญลักษณ์เฉพาะที่มีอยู่เดิมคงไว้
- `components/game/scene-text.tsx`: เพิ่ม SceneText ให้ Text ทุกเส้นทางใช้ฟอนต์เดียว ไม่มี letter spacing บังคับ ค่าเริ่มต้นเส้นขอบบาง .001 และระยะบรรทัดเผื่อภาษาไทย ทั้งนี้ค่าเฉพาะพอร์ต/จอบางจุดยังคงตามบริบทเดิมเพื่อรักษาอัตราส่วนและความต่างพื้นหลัง
- EquipmentNameplate รวมชื่อและข้อความรองไว้ในส่วนเดียว วัด blockBounds หลังจัดตัวอักษรเพื่อวางชื่อเหนือข้อความรองพร้อมช่องว่าง .04 หน่วย ทั้งสองบรรทัดขยายขึ้นจากจุดอ้างอิงเดิม ไม่ขยายลงไปในอุปกรณ์ ข้อความรองว่างไม่สร้างบรรทัดเปล่า ไม่ขยับจุดต่อสายหรือ collider
- `components/game/environment/venue/textures.ts`: ป้ายที่วาดผ่าน tex.sign วาดซ้ำหลัง loadSceneFont สำเร็จและตั้ง needsUpdate รองรับกรณีถูกสร้างนอก main gate เดิม เก็บขนาด texture อัตราส่วน สี และ anisotropy เดิม ไม่เปลี่ยน UV ของโมเดล
- `app/xianxia-theme.css`: เพิ่มตัวแปรบทบาทข้อความใน game-screen และใช้ Sarabun กับคำสั่ง รายละเอียดอุปกรณ์ กระเป๋า สถานะและแผนผัง ลดช่องไฟ/เงาของข้อความใช้งาน ไม่เปลี่ยนโครงหน้า กระเป๋า หรือหน้าใบงาน
- `game/content/sim-thai.ts`: เพิ่มคำแปลชื่อทั่วไป เช่น กล้อง อุปกรณ์รับภาพ คอมพิวเตอร์ (OBS) เครื่องผสมเสียง ไมโครโฟน เครื่องรับ/ส่งไร้สาย และลำโพงตรวจฟัง ค่า id และข้อมูลบันทึกเดิมไม่เปลี่ยน
- `components/game/operator-console.tsx` และ `equipment-inspector.tsx`: ใช้พจนานุกรมแสดงชื่อทั่วไปบางตำแหน่งร่วมกับระบบเดิม ไม่เปลี่ยนคำศัพท์ในพอร์ตจริง

## เวลาโหลดและข้อยกเว้น

GameCanvas รอ loadSceneFont ก่อนเปิดฉากอยู่แล้ว หากโหลดไม่สำเร็จยังมีข้อความและปุ่มลองใหม่ภาษาไทย ไม่ปล่อยให้เข้าเกมพร้อมป้ายที่ใช้ fallback โดยเงียบ ๆ ป้าย Canvas มีการวาดซ้ำเพิ่มเพื่อรองรับการโหลดช้า ส่วน Drei Text ใช้ไฟล์ตรงและระบบจัดอักขระของ renderer

ฟอนต์พู่กันของตรา/ชื่อแบรนด์และหัวข้อประดับยังคงเป็นข้อยกเว้นตามธีมเดิม ไม่แก้เป็นธีมใหม่ ชื่อสินค้า เช่น Yamaha HS5, Magewell, HP และชื่อโมเดลจริงยังคงเดิม HDMI, SDI, XLR, USB, OBS และป้าย INPUT/OUTPUT ที่มีความหมายต่อการฝึกยังคงตัวสะกดจริง คำว่าโปรไฟล์ฝึก/รอยืนยัน/ตามงานอ้างอิงยังอยู่ ไม่มีการรับรองรุ่นหรือพอร์ตเพิ่ม

ป้ายที่ฝังอยู่ใน GLB หรือรูปภาพสำเร็จไม่ได้เปลี่ยนด้วย SceneText และยังต้องตรวจด้วยมือ การเพิ่มระยะบรรทัดไม่ยืนยันว่าทุกป้ายจะไม่ซ้อนกันเมื่อมองจากทุกมุม/ทุกระยะ

## การตรวจที่รันจริง

- `node --test tests/scene-typography.test.mjs tests/mission-foundation-qa.test.mjs`: ผ่าน 7/7 ทดสอบการคงสระ/วรรณยุกต์ ชื่อรุ่นและความไม่แน่นอน คำแปล Computer (OBS) ตาราง shaping ของฟอนต์ และโครงสร้างอุปกรณ์/สายครบ 25 ด่าน
- ตรวจ cmap ของฟอนต์จริงผ่าน FontTools ด้วยตัวอย่าง “กำลัง ห้องฝึก เครื่อง อุปกรณ์”, “คอมพิวเตอร์ (OBS)”, “HDMI IN 1”, “HP 15.6-inch (ตามงานอ้างอิง)”: ไม่พบอักขระขาด และมี GSUB/GPOS
- `npm run lint`: ตรวจใหม่หลังนำเข้า Billboard ที่ไม่ได้ใช้ออก ไม่มีการปิดกฎ lint เพื่อหลบปัญหา
- `npm run build`: ตรวจ compilation, TypeScript และการสร้างเส้นทาง
- `git diff --check` และ `git status`: ตรวจหลังแก้ ไม่ commit/push รักษางานค้างเดิม ไม่แก้ .env.local, progress หรือระบบผู้ดูแล

## สิ่งที่ยังต้องตรวจด้วยมือ

1. ระบุป้ายจากภาพล่าสุดแล้วเทียบกับแหล่งข้อมูลจริงก่อนสรุปว่าสาเหตุตรงกัน
2. เทียบชื่อคอมพิวเตอร์และรุ่น HP รวมป้ายชื่อสั้น/ยาว/ไม่มีรุ่น ในห้องฝึกอิสระและตัวแทนทั้งห้าสถานที่
3. เดินเข้าใกล้/ถอย/อ้อมหลัง ตรวจขอบป้าย ตัวหนังสือบนพื้นสว่าง การบังพอร์ต และ title/subtitle หลัง font sync
