## 2. ห้องฝึกอิสระกับหน้าบรีฟภารกิจ
ห้องฝึกอิสระใช้คลาส `.briefing-cards` / `.briefing-card` / `.briefing-card-icon` ชุดเดียวกับหน้าบรีฟภารกิจ ทั้งประโยคเปิด การ์ด ไอคอน และแถบปุ่มล่าง เนื้อหาเขียนเฉพาะสำหรับการฝึกแบบเปิด:
- **ห้องฝึกอิสระคืออะไร:** ห้องสตูดิโอพร้อมอุปกรณ์ครบเส้นทาง
- **เป้าหมายการฝึก:** เข้าใจอุปกรณ์และสังเกตผล ไม่มีเงื่อนไขผ่านบังคับ
- **สิ่งที่ผู้เล่นจะทำ:** เลือกสายจากโต๊ะสาย → เข้าห้อง → ดูรายละเอียด หยิบ วาง เสียบ → สังเกตผลและแก้
- **ข้อควรรู้ก่อนเริ่ม:** OUTPUT→INPUT, หัวต่อต้องตรงชนิด, การบันทึก/เล่นต่อ (มีอยู่จริงใน `game/persistence/run-save.ts`)

ไม่มีรหัสด่านหรือคำว่าต้องผ่าน 5 ระดับ ภาพเส้นทางนามธรรมด้านขวายังอยู่เหมือนเดิม และหน้าบรีฟภารกิจยังไม่เฉลยตามหลักเดิม

## 3. เนื้อหาแท็บคำชี้แจงที่ปรับใหม่ (อ้างอิงจากโค้ดจริง)
- **คำชี้แจง:** อธิบาย etcstream สั้นๆ, แยกโหมดภารกิจ (5 สถานที่ × 5 ระดับ) จากห้องฝึกอิสระ, สิ่งที่จะได้เรียนรู้, ควรเริ่มที่ไหน
- **บริบท:** "ปราณสัญญาณ" เชื่อมกับงานโสตทัศน์จริง, ต้นทาง→ประมวลผล→ปลายทาง, ห้าสถานที่ที่ยากขึ้น (ระดับสูงคำใบ้น้อยลง ตาม `stage.guidance`), อุปกรณ์จำลองที่รุ่นยังรอยืนยัน (ตาม `GenericLabel`)
- **วิธีเล่น:**
  - ลำดับจริง: ภารกิจ = บรีฟ → เตรียมสาย → ห้อง
  - ปุ่มคอมพิวเตอร์ตาม `first-person-controller.tsx`:
    - เดินและมอง: `W A S D` / เมาส์
    - จัดการอุปกรณ์และสาย: `E` หยิบ/เสียบ/ถอด, `E` ค้าง 2 วินาทีดูรายละเอียด, `F` วาง, `T` หมุน 45°, `1`/`2` + `E` เลือกหัว/ปลายสาย
    - เปิดหน้าต่าง: `R` กระเป๋า (`app/play/page.tsx`), `C` คอนโซล
  - ปุ่มจอสัมผัส (ใช้งาน / วาง / หมุน / 1 / 2 และปุ่มทิศทาง)
  - การตรวจกระเป๋าแบบตรงทุกเส้น และการเล่นต่อจากครั้งล่าสุด
- **กฎสำนัก:** ต่อให้ถูกทิศและถูกชนิด, การนับความผิด (หยิบแล้ววางคืนไม่นับ), กระเป๋าต้องพอดีโดยไม่เฉลย, ผ่านเมื่อระบบทำงานและทดสอบผ่าน, แก้สายหลังทดสอบต้องทดสอบใหม่, งานกลางแจ้งต้องประเมินความปลอดภัยก่อนเริ่ม
- **บทบาท:** ผู้ฝึกงาน AV/สตรีมมิ่ง, สิ่งที่ต้องดูแลแยกเป็นต้นทาง / ประมวลผล / ปลายทาง, การเลื่อนขั้นด้วยคุณความดี (`meritFor`, `rankFor`)

โครงหน้าต่างยังเหมือนเดิม ทั้งภาพอาจารย์สองท่าน แท็บ 5 แท็บ ปุ่ม `ย้อนกลับ` ช่องติ๊ก `ไม่แสดงอีกในครั้งถัดไป` (ยังใช้ key `streamlab_skip_intro`) และปุ่ม `ปิดจารึกและดำเนินต่อ` เนื้อหายาวเลื่อนในกล่องเดียว (`.modal-content-scroll`)

## 4. ปุ่ม X ที่ลบ และที่ยังคงไว้
- **ลบจุดที่ 1:** `components/ui/instructions-modal.tsx` ปุ่ม `.modal-close-x` (`aria-label="ปิดหน้าต่าง"`) ในส่วนหัวของหน้าคำชี้แจง ส่วนหัวจัดเรียงใหม่เองเพราะเหลือแค่ปุ่มย้อนกลับกับแท็บ หน้าต่างนี้ไม่มีการปิดด้วย Esc หรือคลิกพื้นหลัง จึงออกได้ทางปุ่มที่ระบุเท่านั้น
- **ลบจุดที่ 2:** `components/ui/cable-lobby.tsx` ปุ่ม `.cl-warn-x` ของกล่องเตือนสีแดง และเลิกปิดเมื่อคลิกพื้นหลัง ยังปิดได้ด้วยปุ่ม `กลับไปจัดกระเป๋า` และ Esc (เพื่อการเข้าถึง) โดยไม่ล้างกระเป๋าและไม่เข้าด่าน ตัวตรวจกระเป๋าไม่ได้แก้
- **ไม่ได้แตะ:** ปุ่ม ✕ นำสายออกจากช่องกระเป๋า (`.cl-bag-remove`), ปุ่มปิดของหน้าดูรายละเอียดอุปกรณ์, คอนโซล, หน้าต่างอื่น และ CSS กลาง `.modal-close-x`

## 5. สาเหตุที่หน้าหน่วง และวิธีแก้
**สิ่งที่พบในโค้ด** (ยังไม่ได้วัดด้วย profiler):
1. **เมฆลอย:** หน้าคำชี้แจงเปิดบนหน้าแรก (`FantasyBackground clouds`) ซึ่งมีเมฆเต็มจอ 3 ชั้น (`CloudSky`) ที่เลื่อนด้วยการเปลี่ยน `background-position` ทำให้ต้องวาดใหม่ทั้งจอทุกเฟรม และชั้นหน้าสุดมี `filter: blur(1.5px)` ด้วย
2. **พื้นหลังเบลอ:** ฉากหลังของหน้าคำชี้แจงใช้ `backdrop-filter: blur(10px)` เต็มจอ เมื่อพื้นหลังเปลี่ยนทุกเฟรม เบราว์เซอร์ต้องเบลอใหม่ทุกเฟรม รวมกับข้อ 1 กลายเป็นงานหนักที่สุดของหน้านี้
3. **parallax:** ยังอัปเดตตามเมาส์ทั้งที่ท้องฟ้าถูกหน้าต่างบังอยู่
4. **ภาพอาจารย์:** ภาพขนาดใหญ่สองภาพมี `drop-shadow` และแอนิเมชันเลื่อนเข้า และไม่มี `sizes` ทำให้อาจโหลดภาพใหญ่กว่าที่แสดง
5. **เนื้อหาแท็บ:** เป็น JSX ยาวที่ถูกสร้างใหม่ทุก render (ผลไม่มาก)
6. **หน้าเล่นเกม:** ฉาก 3D หลังหน้าบรีฟใช้ `frameloop="demand"` อยู่แล้วเมื่อไม่ active จึงไม่ใช่สาเหตุ ไม่ได้แก้

**สิ่งที่แก้:**
- เมฆเลื่อนด้วย `transform: translate3d` บนแถบที่กว้างกว่าจอหนึ่งแผ่นลาย ความเร็วและหน้าตาเท่าเดิม แต่ GPU จัดการได้โดยไม่ต้องวาดใหม่
- ขณะหน้าคำชี้แจงเปิด ตั้ง `html[data-overlay="guide"]` เพื่อหยุดแอนิเมชันเมฆ ภาพพื้นหลัง และหมอก และไม่อัปเดต parallax ปิดหน้าต่างแล้วทุกอย่างกลับมาเล่นต่อ
- จอสัมผัสหรือจอเล็กไม่ใช้ backdrop blur แต่ใช้พื้นทึบขึ้นแทน
- ภาพอาจารย์ใช้ `will-change` เพื่อให้ shadow ถูกวาดครั้งเดียว และใส่ `sizes="600px"`
- เนื้อหาแท็บเป็นค่าคงที่ระดับโมดูล

**ที่ยังไม่ได้วัด:** ความลื่นจริงยังไม่ได้วัด ไม่มีตัวเลข FPS และไม่รับประกันว่าไม่มีกระตุกเลยในทุกเครื่อง
