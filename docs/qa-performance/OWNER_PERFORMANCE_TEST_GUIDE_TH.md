# คู่มือทดสอบความลื่นสำหรับเจ้าของโครงการ

**แบบฟอร์มบันทึก (ทุกครั้งที่พบอาการ):**
`อุปกรณ์ | OS/เบราว์เซอร์ | ขนาดจอ/แนว | โหมด/ด่าน | การกระทำ | อาการ (ค้าง/กระตุก/ช้า) | เกิดซ้ำได้ไหม | ข้อความใน Console | FPS/หน่วยความจำ (ถ้าวัด)`

วัด FPS ได้ที่ Chrome DevTools → Rendering → Frame Rendering Stats และวัดเวลาที่ใช้ได้ที่ Performance → Record

- [ ] **1. หน้าแรกและหน้าคำชี้แจง:** เปิดหน้าคำชี้แจงซ้ำ 5–10 ครั้ง สลับแท็บ และเลื่อนเนื้อหา ต้องไม่ช้าลงเรื่อยๆ ปิดแล้วเมฆลอยต่อลื่น
- [ ] **2. หอภารกิจ:** ไล่ดูบททั้ง 5 และระดับทั้ง 25 → บรีฟ → หน้าเตรียมสาย ลองค้นหา สลับหมวด ปรับจำนวน ใส่และนำออกจากกระเป๋า ต้องตอบสนองทันที
- [ ] **3. เข้าออกห้อง:** เข้าห้องแต่ละประเภท (XS, ST, AU, OUT, SP) เดิน มอง กดค้างดูรายละเอียด → ออก → เข้าใหม่ 3–5 รอบ ดูว่าค่อยๆ หน่วงขึ้นหรือไม่
- [ ] **4. ทำหลายอย่างพร้อมกัน:** ย้ายอุปกรณ์ หยิบและเสียบสาย เปิดกระเป๋า (R) และคอนโซล (C) ระหว่างเดิน ดูว่ามีกระตุกหรือไม่ **โดยเฉพาะการหันกล้องผ่านพอร์ตจำนวนมาก** ซึ่งเป็นจุดที่แก้ในรอบนี้
- [ ] **5. ด่านใหญ่:** SP-05 (ผ่านหน้าผู้ดูแลจะได้สาย 50 เส้นในกระเป๋า) ต่อสายจำนวนมาก แล้วดูความลื่นตอนหันกล้อง
- [ ] **6. ความถูกต้องของสัญญาณ:**
  - ต่อระบบจนสัญญาณขึ้น → ถอดสายสำคัญหนึ่งเส้น → จอหรือสถานะต้องเปลี่ยนทันที และส่งงานไม่ได้
  - ต่อกลับ → ต้องทดสอบใหม่
- [ ] **7. บันทึกและเล่นต่อ:** ออกจากห้อง → เล่นต่อ ห้องต้องเหมือนเดิม ไม่มีสายซ้ำ และไม่ค้างตอนกู้คืน
- [ ] **8. ห้องฝึกอิสระ:** เข้า ออก แล้วเข้าใหม่ ต้องลื่น และมีบันทึกแยกจากภารกิจ
- [ ] **9. อุปกรณ์ต่างๆ:**
  - Chrome บนเดสก์ท็อป, Safari บน iPhone และ iPad, เบราว์เซอร์ Android (ถ้ามี)
  - หมุนจอแนวตั้งและแนวนอน
  - สลับแอปบน iOS แล้วกลับมา
- [ ] **10. เปรียบเทียบ:** ถ้าเป็นไปได้ ให้บันทึก FPS ช่วงเดิน/หันกล้องในห้อง SP ก่อนและหลังอัปเดต (ใช้ commit ก่อนหน้าเทียบ)

**ลำดับที่ควรทดสอบก่อน:**
1. ข้อ 4 และ 5 (จุดที่แก้หลัก)
2. ข้อ 6 (ยืนยันว่าความถูกต้องไม่เปลี่ยน)
3. ข้อ 7 และ 9 (iPhone)
