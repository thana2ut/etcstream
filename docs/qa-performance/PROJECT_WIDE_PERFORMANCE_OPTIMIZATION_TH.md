# ปรับประสิทธิภาพทั้งโปรเจกต์ (รอบนี้)

วันที่: 2026-10-20 · ยังไม่ได้ commit · **ยังไม่ได้วัดผลจริงบนอุปกรณ์ ไม่มีตัวเลข FPS ก่อนหรือหลังแก้**

## 1. สิ่งที่พบ
### พบในโค้ดและแก้แล้ว
1. **ระบบจำลองสัญญาณคำนวณใหม่บ่อยเกินจำเป็น (ผลมากที่สุด):**
   - `simContext()` ใน `game/training/hdmi-training.ts` แคชผลไว้ตาม object ของ state ทั้งก้อน
   - ใน store ทุกการเปลี่ยนแปลงสร้าง state object ใหม่ เช่น เปลี่ยนเป้าเล็ง (`focusedTarget` เปลี่ยนทุกครั้งที่มองผ่านพอร์ตหรืออุปกรณ์), ตัวจับเวลากดค้าง E, ข้อความแจ้งเตือน หรือเปิดคอนโซล
   - แต่ละครั้งจึงคำนวณกราฟสัญญาณใหม่ทั้งหมด (`evaluate`) แม้สายและการตั้งค่าไม่เปลี่ยนเลย
   - มีหลายจุดที่เรียก `simContext()` ใน selector ของ store รวม 20 จุด เช่น ไฟ tally ของกล้องทุกตัว, จอทุกจอ, ไฟ rack, HUD และคอนโซล ห้องใหญ่อย่าง SP จึงเสียแรงมากขึ้นตามจำนวนอุปกรณ์ ทุกครั้งที่หันกล้อง
2. **Canvas re-render ทุกครั้งที่อุปกรณ์ขยับ:** `GameCanvas` subscribe `state.items` เพื่อใช้กับเครื่องมือตรวจฉากของนักพัฒนาเท่านั้น ทำให้ทั้ง component ของ canvas re-render ทุกครั้งที่ย้ายหรือวางอุปกรณ์
3. **การบันทึกอัตโนมัติ:** `pickTraining()` คัดลอก state ลึกด้วย `JSON.parse(JSON.stringify(...))` ทุกครั้งที่บันทึก รวมถึง `sim.log` ที่ยาวขึ้นเรื่อยๆ และ `writeRun` ยัง serialize ซ้ำอีกรอบ
4. **ความเสี่ยงฝั่ง React (lint `react-hooks`):**
   - `run-persistence.tsx` เขียน ref ระหว่าง render
   - `app/play/page.tsx` เรียก setState ทันทีใน effect 3 จุด (ตรวจบันทึกเล่นต่อ, สถานะผู้ดูแล, เตรียมสายผู้ดูแล) ซึ่งอาจทำให้ render ต่อกันเป็นทอดๆ
5. **รอบก่อนหน้า (ยังมีผล):**
   - เมฆบนหน้าแรกเลื่อนด้วย `background-position` ซึ่งต้องวาดใหม่ทุกเฟรม รวมกับฉากหลังเบลอเต็มจอของหน้าคำชี้แจง แก้แล้วในรอบ PREGAME (ใช้ transform และหยุดเมื่อมี overlay)
   - ป้ายคำสั่งย่อชื่อที่ต้นทาง

### ตรวจแล้ว ไม่ใช่ปัญหา หรือมีการจัดการอยู่แล้ว
- **Canvas:** ใช้ `frameloop="demand"` เมื่อไม่ได้เล่น (หน้าบรีฟ/คอนโซล/กระเป๋า) และมี `PerformanceMonitor` ปรับ DPR อัตโนมัติ (0.6–1.25)
- **เป้าหมายที่เล็ง:** raycast เป้าหมายอัปเดต store เฉพาะเมื่อเป้าเปลี่ยน (`focus` เทียบ key)
- **สาย:** ส่วนของสายที่วางนิ่งไม่ถูกคำนวณใหม่ (`last.current` equals) สายในภารกิจใช้ `InstancedMesh`
- **การบันทึก:** debounce 400ms, เขียนเฉพาะเมื่อข้อมูลโลกเปลี่ยน และไม่บันทึกตอนหันกล้อง

### ยังสงสัย แต่ไม่ได้แก้ (ยังไม่ได้วัด)
- `first-person-controller.tsx` ไล่ scene graph ทั้งหมดทุก 10 เฟรมเพื่อหาเป้าหมายและสิ่งกีดขวาง ห้อง SP ที่มีวัตถุมากอาจกินเวลา ควรวัดด้วย Performance panel ก่อนตัดสินใจลดความถี่ เพราะกระทบความแม่นในการเล็ง
- `TrainingHud` และ `OperatorConsole` subscribe ทั้ง store จึง re-render เมื่อเป้าเล็งเปลี่ยน หลังแก้ข้อ 1 การ render แต่ละครั้งเบาลงมาก การแยก selector เป็นงาน refactor ที่ใหญ่กว่าขอบเขตนี้
- `sim.log` ยาวขึ้นเรื่อยๆ ในเซสชันยาว ทำให้บันทึกใหญ่ขึ้น ยังไม่ได้ตัดทอน เพราะ log เป็นหลักฐานในคอนโซล

## 2. ไฟล์และฟังก์ชันที่แก้
| ไฟล์ | สิ่งที่แก้ | เหตุผล |
|---|---|---|
| `game/training/hdmi-training.ts` `simContext` | แคชตาม input จริง (`scenarioId, cables, items, heldItem, bagged, hiddenCables, sim`) โดยเทียบ reference นอกเหนือจาก WeakMap เดิม | ตรวจแล้วทุก reducer สร้าง object ใหม่เมื่อข้อมูลเหล่านี้เปลี่ยน (`cloneCables`, `{ ...state.sim }`, `items` ใหม่) การเทียบ reference จึงรู้การเปลี่ยนแปลงได้ตรง ไม่มีผลค้าง |
| `components/game/game-canvas.tsx` | selector `state.items` คืน `null` เมื่อไม่ได้เปิดโหมดตรวจฉาก | ผู้เล่นไม่ทำให้ canvas re-render ทุกครั้งที่ขยับอุปกรณ์ |
| `game/persistence/run-save.ts` `pickTraining` | เลิกคัดลอกลึก ใช้ reference เดิม (state immutable) | serialize ครั้งเดียวต่อการบันทึก |
| `components/game/run-persistence.tsx` | อัปเดต ref ใน `useLayoutEffect` | ไม่เขียน ref ระหว่าง render |
| `app/play/page.tsx` | ตรวจบันทึกเล่นต่อและเตรียมสายผู้ดูแลใน `setTimeout(0)` พร้อม cleanup / อ่านสถานะผู้ดูแลด้วย lazy `useState` | ไม่มี setState ต่อกันเป็นทอดใน effect และรองรับ Strict Mode (cleanup รีเซ็ต guard) |

## 3. ผลต่อแต่ละส่วน (คาดจากโค้ด ยังไม่ได้วัด)
- **หน้าแรก / หน้าคำชี้แจง:** เมฆใช้ transform และหยุดขณะมี overlay (รอบก่อน)
- **ในห้อง 3D:**
  - การหันกล้องผ่านพอร์ต อุปกรณ์ หรือสาย ไม่ทำให้ต้องคำนวณกราฟสัญญาณใหม่แล้ว
  - การย้ายอุปกรณ์ไม่ทำให้ canvas ทั้งก้อน re-render
  - ห้องที่อุปกรณ์มาก (AU-05, OUT-05, SP-03/05) น่าจะได้ผลมากที่สุด
- **ระบบจำลองสัญญาณ:** กราฟคำนวณใหม่เมื่อสาย ตำแหน่งอุปกรณ์ สิ่งที่ถือ กระเป๋า หรือการตั้งค่า/ผลทดสอบเปลี่ยนเท่านั้น
  - กฎทุกข้อเหมือนเดิม
  - ถอดสายสำคัญแล้ว `cables` เปลี่ยน กราฟจึงคำนวณใหม่ทันที และสถานะผ่านจะหายตามเดิม
  - **ยืนยันด้วยการรันชุดเทสต์ทั้งแบบเปิดและปิดแคช: ผลเหมือนกันทุกข้อ**
- **การบันทึก/เล่นต่อ:** จังหวะการบันทึก ลำดับ revision และการบันทึกทันทีตอนออกไม่เปลี่ยน แค่ลดงาน serialize
- **ผู้ดูแล / ห้องฝึกอิสระ / ขั้นตอนผู้เล่นปกติ:** ลำดับการทำงานเหมือนเดิม การตรวจบันทึกเล่นต่อและการเตรียมสายผู้ดูแลช้าลงหนึ่ง task (ไม่กี่ ms) ระหว่างนั้นผู้ดูแลยังเห็นหน้า "กำลังเตรียมสาย…"
- **การโต้ตอบในห้อง:** หยิบ, วาง, กดค้าง 2 วินาที, ป้ายคำสั่ง, มือ และ HUD ไม่ได้แก้ในรอบนี้

## 4. iPhone / มือถือ
- **ที่มีอยู่แล้ว:** DPR ปรับเองโดย `PerformanceMonitor` และ canvas หยุดวาดเมื่อมี overlay
- **รอบก่อนหน้า:** บนจอสัมผัสเลิกใช้ฉากหลังเบลอ และเมฆหยุด
- **รอบนี้:** การลดการคำนวณกราฟสัญญาณช่วย CPU มือถือโดยตรง เพราะเครื่องช้ากว่าแต่ทำงานเท่ากันทุกครั้งที่หันกล้อง
- **ข้อจำกัด:** Safari บน iOS อาจจำกัด WebGL memory และ localStorage ในโหมดส่วนตัว
