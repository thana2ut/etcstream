# บันทึกและเล่นต่อจากการฝึกล่าสุด (ทุกโหมด)

วันที่: 2026-10-20 · ยังไม่ได้ commit

## 1. สาเหตุจริง
- **ข้อมูลห้องไม่เคยถูกบันทึก:** สถานะห้อง (สาย อุปกรณ์ กระเป๋า การตั้งค่าเครื่อง) อยู่ใน `useTrainingStore` (zustand) ซึ่งอยู่ในหน่วยความจำอย่างเดียว ส่วนที่บันทึกถาวรคือความคืบหน้าของสำนัก (`etcstream-mission-progress-v1:*`) เท่านั้น จึงเกิดอาการ "ความคืบหน้ายังอยู่ แต่ห้องกลับเป็นค่าเริ่มต้น"
- **กลับเข้าห้องจากสำนัก:** ระบบพาผ่านหน้าบรีฟและหน้าเตรียมสาย (`bag === null`) แล้วปุ่มยืนยันกระเป๋าเรียก `resetTraining(...)` ใน `app/play/page.tsx` ซึ่งสร้างห้องใหม่จากค่าเริ่มต้นของด่าน โต๊ะ/โน้ตบุ๊กที่ย้ายไว้จึงหายไป
- **รีเฟรชหรือเปิดเบราว์เซอร์ใหม่:** store เริ่มจาก `initialTrainingState()` ไม่มีข้อมูลห้องเหลืออยู่เลย

## 3. ที่เก็บข้อมูลและการแยกบันทึก
- **ที่เก็บ:** `localStorage` ของเบราว์เซอร์ ข้อมูลมีขนาดเล็ก (JSON ไม่กี่ KB ถึงหลักสิบ KB) และการเขียนแต่ละ key เสร็จในครั้งเดียว บันทึกนี้อยู่ในเบราว์เซอร์และโปรไฟล์เดียวกันเท่านั้น **ไม่มีการซิงก์ข้ามเครื่อง**
- **รูปแบบ key:** `etcstream-run-v1:<playerId>:<mode>:<scenarioId>`
  - `playerId` มาจาก `streamlab-player-v1` ของระบบผู้เล่นเดิม (ไม่ใช่ชื่อเล่น)
  - `mode` มีสามค่า:
    - `mission` ผู้เล่นปกติ
    - `mission-admin` เข้าผ่านหน้าผู้ดูแล (มีธง `selected.admin`) แยกจากบันทึกของผู้เล่น
    - `free-practice` ห้องฝึกอิสระ (`studio-full`)
  - `scenarioId` เช่น `s-2` (ST-02), `xl-5` ทุกด่านจึงมีบันทึกแยกกัน
- ความคืบหน้าของสำนัก (ด่านที่ผ่านแล้ว การปลดล็อก) ยังอยู่ใน key เดิมและไม่ถูกแก้

## 4. สิ่งที่บันทึก / ไม่บันทึก
**บันทึก** (ข้อมูลหลักของ `TrainingState` ทั้งหมดเป็น JSON ล้วน):
- `cables`: ปลายสายทั้งสองข้างของทุกเส้น แต่ละข้างเก็บพอร์ตที่เสียบหรือตำแหน่งที่วาง จึงเก็บการต่อสายครึ่งเดียวได้
- `bagged`: สายที่ยังอยู่ในกระเป๋า
- `hiddenCables`: สายที่ไม่ได้นำเข้ามาในด่าน
- `held` / `heldItem` / `heldTurn`: สิ่งที่ถืออยู่ในมือ
- `items`: ตำแหน่งและมุมหมุนของอุปกรณ์ที่ย้ายได้ทุกชิ้น เช่น โน้ตบุ๊กบนโต๊ะกลม
- `actionsDone`, `programSource`
- `sim`: การตั้งค่าเครื่องทุกเครื่อง (ไฟ โหมด แหล่งภาพ ระดับเสียง ปิดเสียง ฯลฯ), ผลทดสอบ, fault ที่ยังเกิดอยู่ / แก้แล้ว, สภาพอากาศ, หลักฐานงาน, คิวรายการ, สถานะ pause/review, จำนวนครั้งที่ผิด
- `wrongStreak`, `failed`
- กระเป๋าที่จัดจากหน้าเตรียมสาย (`lobbyBag`)
- ข้อมูลกำกับ: `schema`, `rev`, `savedAt`, `key`, `contentSig`

**ไม่บันทึก:**
- ข้อความแจ้งเตือน, เป้าเล็ง/hover, การล็อกเมาส์, หน้าต่างที่เปิดค้าง (ผู้ตรวจอุปกรณ์/คอนโซล), สถานะการกดค้าง
- วัตถุ Three.js / mesh / Rapier, ภาพหรือเสียง
- เส้นทางสัญญาณและเครื่องหมายถูกในรายการตรวจ เพราะคำนวณใหม่จากสถานะที่กู้คืน (`simContext`, `requirementDone`, `trainingProgress`) ป้ายเขียวเก่าจึงไม่ถูกเชื่อถือ
- ตำแหน่งและมุมมองของผู้เล่น: กลับเข้าห้องแล้วเกิดที่จุดเริ่มต้นปลอดภัยของห้องเสมอ
- รหัสผ่านหรือข้อมูลผู้ดูแล

## 5. จังหวะการบันทึก
- **เข้าห้องแล้ว** (`inRoom` = มีกระเป๋า, ปิดหน้าบรีฟแล้ว, ด่านโหลดตรงกัน): บันทึกครั้งแรกทันที
- **หลังทุกการเปลี่ยนแปลงที่มีผล** ได้แก่ หยิบ วาง ติดตั้ง หมุน เสียบ/ถอดปลายสาย ใส่/เอาออกจากกระเป๋า ปรับเครื่อง ทดสอบ หรือแก้ fault
  - ระบบจะรอให้หยุดเปลี่ยน 0.4 วินาทีแล้วบันทึกครั้งเดียว
  - ข้อความแจ้งเตือนและการเล็งเป้าไม่ทำให้บันทึก
- **บันทึกทันที:**
  - เมื่อแท็บถูกซ่อน (`visibilitychange` → hidden, รองรับ iPhone Safari เวลาสลับแอป) และเมื่อออกจากหน้า (`pagehide`)
  - ก่อนกด "ออกจากห้องฝึก": ถ้าบันทึกไม่สำเร็จจะไม่ออก และแสดง "บันทึกไม่สำเร็จ โปรดลองอีกครั้ง" พร้อมปุ่มลองใหม่
  - เมื่อออกจากห้องด้วยวิธีอื่น ระบบจะบันทึกสิ่งที่ยังค้างอยู่
- **ไม่ใช้ `beforeunload`**
- **ลำดับการเขียน:** `rev` เพิ่มขึ้นทีละหนึ่งและการเขียนทำทีละครั้ง ข้อมูลเก่าจึงเขียนทับข้อมูลใหม่ไม่ได้
- **เขียนไม่สำเร็จ** (เช่น พื้นที่เต็มหรือถูกบล็อก): บันทึกเดิมที่ดีอยู่แล้วยังคงอยู่ และแสดงสถานะผิดพลาด ไม่แสดงว่าบันทึกแล้วหากยังไม่ได้บันทึกจริง
- **ด่านจบแล้ว** (`completed`): ลบบันทึกของด่านนั้น เพื่อไม่ให้เล่นต่อหรือรับรางวัลซ้ำ

## 6. ลำดับการกู้คืน
1. หน้าเล่นรู้ผู้เล่น โหมด ด่าน และระดับ แล้วสร้าง `runKey`
2. ก่อนแสดงหน้าบรีฟ เรียก `loadRun` เพื่ออ่านและตรวจบันทึก โดยไม่เขียนหรือลบอะไร
3. ถ้ามีบันทึก จะแสดงหน้าต่าง **พบการฝึกที่ยังดำเนินอยู่** พร้อมชื่อด่านและเวลาบันทึกล่าสุด ปุ่ม:
   - `เล่นต่อจากครั้งล่าสุด`
   - `เริ่มใหม่` (มีหน้ายืนยันซ้ำ)
   - `กลับหน้าสำนัก`
4. **เล่นต่อ:**
   - สร้างด่านจากข้อมูลปัจจุบัน (`resetTraining`) แล้วใส่สถานะจากบันทึก (`useTrainingStore.setState`) ก่อนเข้าห้อง
   - ใช้กระเป๋าเดิม ไม่ผ่านหน้าเตรียมสาย
   - เส้นทางสัญญาณและรายการตรวจคำนวณใหม่จากสถานะที่กู้คืน
5. **เริ่มใหม่:** ยกเลิกการบันทึกที่ค้างอยู่ แล้วลบเฉพาะบันทึกของด่านนี้ จากนั้นเข้าสู่ขั้นตอนเดิม (บรีฟ → เตรียมสาย → ห้อง)
6. การบันทึกอัตโนมัติเริ่มหลังเข้าห้องแล้วเท่านั้น จึงไม่มีจังหวะที่ค่าเริ่มต้นของห้องไปเขียนทับบันทึกเดิมตอนเปิดหน้า
7. ระบบตรวจบันทึกเพียงครั้งเดียวต่อ key (ใช้ `resumeKeyRef`) การ remount, Strict Mode หรือ hot reload จึงไม่ทำให้ห้องรีเซ็ต

## 7. กลับสำนักแล้วเข้าใหม่
- **กด "ออกจากห้องฝึก":** บันทึกทันทีก่อนกลับหอภารกิจหรือสำนัก
- **เลือกด่านเดิมอีกครั้ง:** หน้าต่างเล่นต่อจะแสดง
- **เลือกด่านอื่น:** ใช้ key ต่างกัน ไม่ทับกัน

## 8. ความเข้ากันได้และการย้ายข้อมูล
- `contentSig` คือลายนิ้วมือของรายการพอร์ต สาย และอุปกรณ์ที่ย้ายได้ของด่าน ถ้าเนื้อหาด่านเปลี่ยนรูปร่างหรือบันทึกเสียหาย หน้าต่างจะแจ้งว่า **พบบันทึกการฝึกที่ต้องตรวจสอบ** พร้อมเหตุผลเป็นภาษาไทย บันทึกเดิมยังเก็บไว้ ผู้เล่นเลือกเริ่มใหม่หรือกลับหน้าสำนักได้ ระบบไม่สร้างพอร์ตปลอมเพื่อให้บันทึกเก่าใช้ได้
- `loadRun` ตรวจสิ่งต่อไปนี้:
  - schema, เจ้าของ key, รายการสายตรงกับด่าน, พอร์ตมีอยู่จริง
  - หนึ่งพอร์ตมีสายเสียบได้เส้นเดียว
  - สายไม่อยู่ทั้งในกระเป๋าและในห้องพร้อมกัน
  - อุปกรณ์และสิ่งที่ถืออยู่มีอยู่ในด่านจริง
- ไม่มีการย้ายข้อมูลเก่า เพราะก่อนหน้านี้ไม่เคยมีบันทึกห้อง

## 9. ข้อจำกัด
- ไม่มีตัวจับเวลาด่านให้บันทึก เพราะโหมดปัจจุบันไม่มีตัวจับเวลาที่มีผลต่อการตัดสิน
- สิ่งที่ถืออยู่ตอนออกจะกู้คืนกลับมาอยู่ในมือ (สถานะเป็นข้อมูลล้วน ภาพจะแสดงตามนั้น) ยังไม่ได้ตรวจด้วยตา
- ถ้าเบราว์เซอร์ถูกปิดแบบบังคับก่อนการบันทึกล่าสุด (ภายใน 0.4 วินาทีหลังการกระทำสุดท้าย) การกระทำนั้นอาจหายไป
- โหมดส่วนตัว / Safari ที่บล็อก storage จะบันทึกไม่ได้ และจะแสดงสถานะ "บันทึกไม่สำเร็จ"
- การหักคะแนนหรือยกเลิกการทดสอบเมื่อโครงสร้างสายเปลี่ยน ใช้ตรรกะเดิมของระบบจำลอง การกู้คืนไม่ได้ให้เครดิตเพิ่ม
