# ลำดับเข้าภารกิจ: ใบงาน → เลือกสาย → เล่น

วันที่ 20 ตุลาคม 2026

## ผลการเปลี่ยน

ลำดับจากโค้ดปัจจุบันคือ **Mission click → Briefing → Cable Selection → Enter Mission → Play** สำหรับทางเข้าภารกิจที่รองรับทั้งหมด XS / ST / AU / OUT / SP รวม 25 ด่าน และทางเข้าผู้ดูแลที่ใช้ MissionHall เดียวกัน ห้องฝึกอิสระ mode=classroom ใช้หน้าเตรียมสายร่วมกันอยู่แล้ว จึงใช้ลำดับนี้ด้วย

เดิม `/play` คืน CableLobby ทันทีเมื่อ bag เป็น null ทำให้หน้าเลือกสายแซงหน้าใบงาน จากนั้น callback ยืนยันกระเป๋าตั้ง introOpen=true จึงแสดงใบงานหลังเลือกสาย แก้ที่หน้าเดิม ไม่สร้าง route หรือ component ใบงานซ้ำ

## ไฟล์ที่แก้รอบนี้

- `app/play/page.tsx`: เงื่อนไขหน้าเลือกสายเพิ่ม !introOpen; ปุ่มใบงานเปลี่ยนเป็น “เตรียมสาย” และเพียงปิดใบงาน; ยืนยันกระเป๋าที่ไม่ว่างแล้ว resetTraining ด้วยสายที่เลือก ตั้ง introOpen=false และเริ่มภารกิจทันที; ป้องกัน effect เริ่ม/จบภารกิจและปุ่ม C ระหว่าง bag=null; เพลงยังอยู่ช่วงก่อนเล่นขณะเลือกสาย; retry กลับใบงานก่อนเตรียมสายใหม่
- `components/ui/cable-lobby.tsx`: เพิ่ม backLabel แบบ optional โดยเก็บค่าเดิมสำหรับผู้เรียกอื่น หน้าเล่นส่ง “กลับหน้าใบงาน” และ callback ย้อนอ่านใบงานได้ ไม่กลับหอภารกิจทันที
- `docs/missions/MISSION_ENTRY_FLOW_BRIEFING_THEN_CABLE_TH.md`: รายงานนี้

## ขั้นตอนผู้เล่น

1. เลือกภารกิจจากหอภารกิจหรือหน้าผู้ดูแล การตรวจสิทธิ์/ความก้าวหน้าและ selectMission ใช้ระบบเดิม
2. หน้า `/play` เริ่ม introOpen=true, bag=null จึงแสดงใบงานก่อน มีสถานที่จริงจาก mission.venue ชื่อระดับจาก stage.title รหัสจาก stage.id คำอธิบาย เป้าหมาย ใบงาน stage.ticket รายการเตรียมที่มีอยู่ และภาพรวมเส้นทางสัญญาณ
3. กด “เตรียมสาย”: introOpen=false, bag ยัง null จึงแสดง CableLobby โดยยังไม่เริ่มภารกิจ
4. เลือกสายและใส่กระเป๋าตามสต็อกของภารกิจ ระบบจำกัดจำนวนและขั้นต่ำอย่างน้อย 1 เส้นเดิมยังทำงาน ปุ่มย้อนกลับอ่านใบงานได้ การย้อนออกจากหน้าสายก่อนยืนยันจะเลิกใช้รายการเลือกชั่วคราวของหน้านั้นตามการ unmount เดิม ไม่เขียนความก้าวหน้าที่บันทึกไว้
5. กด “เข้าสู่ด่าน”: callback ตรวจว่ามีสายจริงอย่างน้อย 1 เส้น บันทึกกระเป๋าเฉพาะรอบนี้ จัดสถานะสายผ่าน hiddenCablesFor/packedLeadsFor เดิม และเปิดเล่นทันที ไม่มีใบงานรอบสอง
6. ลองใหม่: กลับหน้าใบงานและเตรียมสายสำหรับรอบใหม่ ไม่ล้างข้อมูลผ่านด่านสะสม

## ตารางสถานะที่ตรวจจากโค้ด

| สถานะ | introOpen | bag | หน้าที่แสดง/ผล |
|---|---|---|---|
| เข้าหน้าเล่นครั้งแรก | true | null | ใบงาน; ไม่เริ่ม mission และ C ไม่เปิดคอนโซล |
| กดเตรียมสาย | false | null | CableLobby; ไม่เริ่ม mission/ไม่ตรวจรับ/เพลงยังช่วงก่อนเล่น |
| กลับหน้าใบงาน | true | null | ใบงานเดิมของด่านที่เลือก |
| ยืนยันกระเป๋าว่าง | false | null | callback ปฏิเสธและยังอยู่หน้าเลือกสาย |
| ยืนยันกระเป๋าถูกกฎ | false | มีค่า | reset สายตามกระเป๋าและเริ่มเล่นโดยตรง |
| ลองใหม่ | true | null | ใบงานก่อนเลือกสายใหม่ |

## ตรวจครบห้าสถานที่อย่างไร

`components/ui/mission-hall.tsx` ฟังก์ชัน startMission ใช้ `/play?mode=mission&mission=...&difficulty=...` ร่วมกันทั้งปกติและ admin ผ่าน selectMission เดิม `app/play/page.tsx` ใช้ scaleByVenue แปลง classroom/studio/auditorium/outdoor/stadium เป็น xs/s/m/l/xl แล้วใช้เงื่อนไขหน้าใบงาน/เลือกสายชุดเดียวกัน ไม่มี branch ข้ามใบงานเฉพาะสถานที่ ไม่แก้ stage, catalog, ports, simulation, authentication หรือ repository ของ progress

## ผลตรวจจริง

- `npm run lint`: ผ่าน
- `npm run build`: ผ่าน compilation, TypeScript และ static routes รวม `/play`, `/missions`, `/missions/admin`
- `node --test tests/mission-foundation-qa.test.mjs`: ผ่าน 5/5 รวมโครงสร้างอุปกรณ์/ปลายสาย/สต็อกครบ 25 ภารกิจ และเงื่อนไขถอดสายสำคัญ
- `git diff --check`: ผ่าน exit 0
- ตรวจ branch/status ก่อนและหลัง: main มีการแก้ค้างจากงานก่อน รักษาไฟล์เหล่านั้น ไม่ commit/push

การตรวจ branch และ callback ของหน้าเข้าภารกิจเป็นการตรวจโค้ด ชุดทดสอบ 5 ข้อข้างต้นตรวจระบบภารกิจและสาย ไม่ใช่การคลิก UI อัตโนมัติ ไม่ได้อ้างว่าทดสอบเดินผ่าน 25 ด่านหรือคลิกจริงใน Chrome รอบนี้

## ข้อจำกัดและสิ่งที่ต้าตรวจต่อ

- ยังไม่ได้ตรวจ UI จริงในเบราว์เซอร์ รอบนี้รักษาสไตล์ใบงาน/ภาพรวมเดิมและปรับข้อมูลที่แสดงจากแหล่งจริง ไม่อ้างว่าจัดวางตรงภาพอ้างอิงทุกพิกเซล
- ให้ลองตัวแทน XS-01, ST-02, AU-01, OUT-03, SP-05 และห้องฝึกอิสระ: เข้าแล้วเห็นใบงานก่อน กดเตรียมสาย ลองกดเข้าตอนว่าง เลือกสายแล้วเข้าห้องโดยไม่เห็นใบงานซ้ำ
- ลองย้อนจากหน้าเตรียมสาย/ย้อนจากใบงาน ลองใหม่หลังจบหรือไม่ผ่าน และ refresh หน้า ตรวจข้อมูลผ่านด่านสะสมยังอยู่
- การ refresh กลับใบงานและต้องจัดกระเป๋ารอบใหม่ รายการเลือกที่ยังไม่ยืนยันไม่ได้บันทึกข้ามการย้อนหน้า ไม่เปลี่ยนให้เป็นระบบบันทึกกระเป๋าถาวร
- ตรวจหน้าจอเตี้ย/มือถือและการโหลดโมเดลจริง ผล build ไม่ยืนยันตำแหน่งปุ่มหรือความลื่นขณะเล่น
