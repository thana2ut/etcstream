# ภาพสายกระเป๋าตรงกับการ์ดสายที่เลือก

วันที่ 20 ตุลาคม 2026

## สาเหตุและสิ่งที่แก้

เดิมรายการสายใช้ `CardCableScene` → `CableModel` ตาม catalog id แต่ช่องกระเป๋าใช้ `ConnectorIcon` ซึ่งแสดงเพียงหัวต่อและเส้นโค้งตาม family จึงไม่ใช่ภาพสายเดียวกัน แม้ข้อมูลสายและจำนวนจะถูกต้อง

แก้ให้ทุกจุดใช้ `CableThumbnail` ใน `components/ui/cable-model.tsx` ซึ่งครอบ `View` และ `CardCableScene` ตัวเดียวกัน การ์ดและช่องกระเป๋าส่ง `CatalogCable` ของรายการนั้นจริงผ่าน prop cable ไม่ใช้รายการที่กำลังเลือกแทนรายการเก่าในกระเป๋า จึงเปลี่ยนหมวด/เลือกสายใหม่ได้โดยภาพของสายเดิมไม่เปลี่ยนตาม

## ไฟล์ที่แก้

- `components/ui/cable-model.tsx`: เพิ่มตัวแสดงภาพร่วม CableThumbnail ใช้มุมกล้อง แสง และ CableModel เดียวกันทั้งการ์ดและกระเป๋า เพิ่ม Bounds fit ให้ย่อภาพตามสัดส่วนช่อง เพิ่ม mapping `AUD-XLR-35` เป็น xlr-f → trs35 ตาม ends ในแค็ตตาล็อกเดิม
- `components/ui/cable-lobby.tsx`: เปลี่ยนการ์ดรายการ ช่องกระเป๋า และ BagOverlay ให้ใช้ภาพร่วม ใช้ CatalogCanvas ร่วมสำหรับบริเวณกระเป๋าโดยไม่สร้าง Canvas ใหม่ต่อช่อง
- `components/game/bag-panel.tsx`: เปลี่ยนภาพรายการสาย/สายที่ถือของห้องฝึกอิสระ และรายการสต็อกภารกิจ ให้ใช้รหัสแค็ตตาล็อกเดียวกัน พร้อม Canvas ร่วมต่อหน้าต่าง
- `app/cable-lobby.css`: กำหนดภาพอยู่ใน hit area เดิม ไม่แก้จำนวนช่อง การเรียงช่อง ขนาดช่อง หรือกฎจำนวนสาย ยกจำนวนและปุ่มนำออกเหนือภาพ Canvas และให้ Canvas ไม่รับ pointer events จำกัดการวาดให้อยู่ในกรอบที่เกี่ยวข้อง

## การจับคู่ข้อมูลและจำนวน

`useCableBag` ยังเก็บจำนวนด้วย catalog id และสร้าง entries ด้วย catalogById เหมือนเดิม การ์ดส่ง c ช่องกระเป๋าส่ง e.c จึงกลับไปใช้แหล่งโมเดลเดียวกัน เพิ่มหลายเส้นยังแสดงภาพเดียวพร้อมจำนวน e.n กดนำออกใช้ remove(e.c) เดิม กดภาพกระเป๋าเลือก e.c เพื่อดูรายละเอียดเดิม ไม่เปลี่ยนสต็อก แพ็กสาย เงื่อนไขเข้าด่าน การหยิบ/เก็บคืน หรือข้อมูลผ่านด่าน

## ครอบคลุมรายการใด

ตรวจแค็ตตาล็อกจริง 42 รายการ มี mapping หัวต่อครบ 42/42 ไม่มีรายการตกไปใช้ box/box เพราะหารหัสไม่เจอ การจับคู่ไม่ได้หมายถึงมีชิ้นงาน 3D เฉพาะรุ่นครบทุกหัวต่อ

| หมวด | ภาพกระเป๋าใช้ภาพเดียวกับการ์ดหรือไม่ | ข้อสังเกต |
|---|---|---|
| video ภาพ | ใช่ | HDMI หลายขนาด / SDI / DP ตามรหัสเดิม |
| audio เสียง | ใช่ | Lavalier, XLR, TRS, TRRS, RCA; เพิ่ม XLR → 3.5 ที่ขาด mapping |
| usb รับภาพ/ข้อมูล | ใช่ | USB แต่ละคู่หัวตาม ENDS เดิม |
| fiber ใยแก้ว | ใช่ | โมเดลจำลองตาม family เดิม ไม่เพิ่มข้ออ้างว่าเป็นหัวจริงเฉพาะรุ่น |
| stagebox สายเวที | ใช่ | Multicore / Dante ตามรายการ |
| network เครือข่าย | ใช่ | Ethernet/PoE ตามรายการ ไม่เปลี่ยนความเข้ากันของสาย |
| control ควบคุม/สายพิเศษ | ใช่ | ใช้โมเดลและหัวตามรหัสเดียวกันกับการ์ด |

ทุกภารกิจ XS / ST / AU / OUT / SP ใช้ CableLobby ร่วมกัน ตรวจ packableCatalogIds ครบ 25 ภารกิจ ไม่มี id ที่หาในแค็ตตาล็อกไม่เจอ ห้องฝึกอิสระ studio-full ใช้ระบบเดียวกัน (รายการแพ็กได้ 11 ชนิด) และภาพกระเป๋าในห้องใช้ CableThumbnail ด้วย

## กรณีภาพสำรองที่ยังเหลือ

CABLE_MODEL_FILES ปัจจุบันยังไม่มีไฟล์ GLB รายการที่ลงทะเบียนจริง ภาพทั้งหมดจึงเป็นโมเดลจำลองจากหัวต่อ PlugMesh กับสายขดเดิมของโครงการ ตอนนี้กระเป๋าใช้โมเดลจำลองนั้นเหมือนการ์ดทุกรายการ ไม่ใช่การเพิ่มไฟล์ภาพถ่ายหรือสร้างโมเดลผู้ผลิตใหม่

หัวที่ใช้ BoxPlug เช่น generic USB-B / replay / tally และ multicore ยังเป็นรูปทรงฝึกเดิม บางรายการที่หัวเหมือนกันจะมีภาพคล้ายกัน จึงยังต้องอ่านชื่อ/หัวต่อในรายละเอียดเพื่อแยกหน้าที่ ไม่สร้างรูปทรงอ้างอิงฮาร์ดแวร์ที่ยังไม่มีหลักฐาน เมื่อเพิ่ม GLB ลง CABLE_MODEL_FILES ภาพการ์ดและกระเป๋าจะใช้ไฟล์ใหม่ผ่าน CableModel เดียวกันโดยไม่ต้องแก้ mapper แยก

## ผลตรวจและสิ่งที่ยังไม่ยืนยัน

- ตรวจ source path ของการ์ด/ช่องกระเป๋า/หน้าต่างกระเป๋าภารกิจและฝึกอิสระ: ใช้ CableThumbnail ร่วมกันแล้ว
- ตรวจ mapping แค็ตตาล็อก: 42 รายการ missing 0
- ตรวจ id สายแพ็กได้ครบ 25 ภารกิจ: ไม่พบรายการที่อยู่นอกแค็ตตาล็อก
- `node --test tests/bag-inventory.test.mjs tests/mission-foundation-qa.test.mjs`: ผ่าน 6/6 รวมการหยิบ วาง หยิบอีกเส้น เก็บคืน และการตรวจอุปกรณ์/สายครบ 25 ภารกิจ การทดสอบนี้ตรวจสถานะจริงของ store ไม่ใช่การคลิกหน้าจอ
- `npm run lint`: ผ่าน
- `npm run build`: ผ่านหลังแก้ รวม TypeScript; การ build รอบแรกพบ CSS ผิดรูปแบบ จึงตรวจ/แก้ไฟล์ CSS แล้ว build ใหม่ผ่าน ไม่ใช่ผลผ่านทุกครั้ง
- `git diff --check`: ผ่าน; ตรวจ branch/status แล้ว รักษางานค้างจากรอบก่อน ไม่ commit/push ไม่แก้ progress/Admin/ไฟล์ลับ

ยังไม่ได้เปิดตรวจ Chrome ในรอบนี้ จึงยังไม่รับรองภาพการวาด WebGL จริง การคลิปขณะเลื่อน รายการเพิ่ม/นำออกด้วยเมาส์ ความคมในช่องเล็ก หรือประสิทธิภาพเครื่องจริง ต้องทดสอบต่อด้วยมือ โดยระบบใช้ Canvas ร่วมสำหรับรายการและกระเป๋าคนละกรอบ ไม่สร้าง context ใหม่ต่อสาย แต่ View ของ drei ลงทะเบียนร่วมกัน จึงควรตรวจภาระการวาดเมื่อมีหลายรายการ

## รายการทดสอบด้วยมือ

1. เปิดตัวแทนแต่ละสถานที่และห้องฝึกอิสระ เลือก HDMI, Lavalier → TX, RX → XLR, Active Speaker, TRS 6.35 → 3.5 และ USB ที่มีในด่าน
2. ใส่กระเป๋า เทียบหัวทั้งสองด้านและสีสายกับการ์ด เปลี่ยนไปเลือกสายอื่นแล้วภาพของรายการเก่าในกระเป๋าต้องคงเดิม
3. เพิ่มจำนวน นำออก 1 เส้น นำออกจนหมด แล้วเพิ่มใหม่ ตรวจจำนวน/ภาพ/การเลือกให้ตรงกัน
4. ลองหลายหมวด รวม fiber/network/control ที่มีจริงในด่าน เลื่อนกริดและกระเป๋า ตรวจภาพไม่ลอยนอกกรอบ
5. ตรวจจอ 1920×1080, 1366×768 และมือถือ ปุ่มนำออกและจำนวนต้องอ่าน/กดได้ ภาพต้องไม่บังข้อความหรือเปลี่ยนจำนวนช่อง
6. เข้าห้อง เปิดกระเป๋า/สต็อก ตรวจภาพสายตรงกับหน้าจัดสาย หยิบและเก็บคืนได้ตามกฎเดิม
