# Production simulation — five rooms × five stages (implementation report)

_2026-10-16 · implements the five room specifications (01 Gate of First Images … 05 Throne of Broadcast)._

## A. Audit — what the project actually is
The specs assume Godot. **EduStream/etcstream is a Next.js 16 + React-Three-Fiber web game** (no `project.godot`). Equivalent integration points that were found and reused:

| Spec concept | Real location |
|---|---|
| Hub / progression / unlocks | `app/missions`, `components/ui/mission-hall.tsx`, `game/persistence/mission-progress-repository.ts` (L(n) unlocks after L(n−1)) |
| Mission catalog | `game/content/mission-catalog.ts` (static, regenerated by `scripts/generate-mission-catalog.mjs`) |
| Room scenes | `components/game/environment/venue/*.tsx` + `game/training/venue-layouts.ts` |
| Movement / interaction | `components/game/first-person-controller.tsx`, `game/training/hdmi-training.ts` (carry, plug, unplug) |
| Inventory | Cable-prep lobby + bag (`components/ui/cable-lobby.tsx`, `components/game/bag-panel.tsx`, `game/content/cable-catalog.ts`) |
| Inspect mode | `components/game/equipment-inspector.tsx` (hold E) |
| Error review loop | previously "5 wrong in a row = fail"; now **3 meaningful errors → Mission Paused → targeted review → mini mastery check → resume** for all 25 stages |

## B. Architecture (new)
`game/training/sim/`
- `types.ts` — `EquipmentDefinition`, `PortDefinition`, `SignalClass`, `Signal`, `DeviceConfig`, `FaultScenario`, `ObjectivePredicate`, `StageManifest`, `SimRuntime`, `EvalContext`.
- `equipment.ts` — manifest: 27 models with `sourceUrl`, `verifiedPorts`, `assetLicense`; named models only where the specs cite a manufacturer page, everything else **Generic Training Device**.
- `engine.ts` — typed directed graph: `canConnect` (reason-coded: direction, input-to-input/return feed, video class, pro→consumer level, speaker/headphone level, USB power-only, LAN vs WAN), `evaluate` (fixed-point propagation of video format/content/embedded audio, analog level/clip, USB roles, Ethernet *control vs stream* decided by the device, storage, ingest/upload), `traceTo` (node → port → cable → node → port with first faulty node + fix), `resolveChain`, `testRoute`, `validateLevel`, `scoreOf` (35/20/15/10/10/10 weights, critical gates, CERTIFIED ≥85 / PASS ≥70 / RETRY).
- `library.ts` — objective builders + 27 learning concepts (review text + mini check).
- `rooms.ts` — the five rooms: fantasy title + English vocational subtitle, instance ids/tags (CL-SW-01…), stations, portable gear.
- `stages.ts` — the 25 `StageManifest`s: ticket, call sheet, captions, canonical graph, start state, faults, surprise-fault pools (L5), cues, preflight, objectives, quiz, reward.

Runtime (`game/training/hdmi-training.ts`, bottom section): `initSim`, `simContext`, `setControl`, `runTest` (physical → signal → rehearsal → delivery, in order), `markTrace`, `streamTest`, `requestAllClear`, `answerQuiz`, `answerReview`, `signOff`, `stageScore`. A stage completes **only** on sign-off after every objective re-validates on the live graph.

`game/training/venue-scenarios.ts` is now an adapter: manifest → 3D Scenario (every modelled port of every device, a cable kit tagged by type/length only, decoys, prewired/faulted start, stored portable gear).

UI: `components/game/operator-console.tsx` (press **C**): Job (ticket, call sheet, captions, preflight/safety + GO/NO-GO, top-down plan, stations), Devices (manifest, source, ports with direction/connector/signal/live signal, controls), Tests & trace, Signal flow (diagram drawn from the actual cables), Run-of-show (PVW/PGM/TAKE, countdown, monitors & meters, evidence/event log, stream tests), Sign-off (mini check, score, reward). `ReviewOverlay` implements the pause loop. Screens/tally in the 3D rooms read the simulated graph (`game/training/monitor-feed.ts`).

## C. How the non-negotiable rules are met
1. Typed graph, output→input only, connector + signal class + format/level + configuration + power + network/storage all required; a plugged cable alone never passes (`tests/production-sim.test.mjs`: "a green cable alone never completes a stage").
2. Distinct classes: HDMI, SDI (format-carrying), MIC, LINE_BAL, LINE_UNBAL, SPEAKER, HEADPHONE, USB_UVC/UAC/STORAGE/POWER, ETHERNET (control vs stream by device), WAN.
3. Reason-coded feedback for every listed fault (power, direction, SDI rate, format mismatch, missing source, embedded audio, mic/line, clipping, mute, routing, uplink, upload, stream key, storage, sync).
4. End-to-end evidence: program/multiview/confidence pictures, meters, recorder files (closed cleanly), mock remote viewer — all local, credentials redacted.
5. Manifest fields present; see `docs/PRODUCTION_EQUIPMENT_MANIFEST.md`.
6. Guided → partial → scenario → disruption → certification; L5 has no route checklist, no prewiring, masked failure reasons and a deterministic per-attempt surprise fault.
7. Deterministic error counting, review loop, scalable console text, text+icon status (✓/✗/★), keyboard (C, Esc), unplug-to-undo.

## F. Known limitations (honest)
- Engine is web/R3F, not Godot. Meshes are original procedural stand-ins; port sockets sit on generic panel layouts, not manufacturer-accurate rear panels. Port names are readable in the console/inspector rather than engraved on meshes.
- Venue scenes reuse the existing enlarged rooms; dimensions differ from the specs (e.g. the stadium is a playable segment, not 110 × 70 m).
- Devices snap to authored stations; cable routes are not drawn — route safety is a preflight attestation plus crossing/ramp flags. Cable ratings/lengths are simulator values.
- Only the ports a stage needs are modelled per named device (listed in each device's notes).
- Score graphics are full-frame only (no fill/key overlay) — documented per SP trap 5.
- Audio levels are discrete states, no audio playback; lip sync is a modelled offset; the 5-minute show and 60/90-s stream tests are compressed into cue sequences and instantaneous checks.
- Optional ST-05 camera return, optional OBS backup (SP) and replay deck are available but not required.
- No gamepad mapping or reduced-motion toggle was added; per-stage score is shown but not persisted (completion is).
- Not committed or deployed.
