# รายงานส่งมอบ Arena V6 — ระบบข้อมูลกลางและแรงก์ฤดูกาล

**IMPLEMENTED — NOT TESTED — OWNER QA REQUIRED**

**แก้ไขโค้ดแล้ว — ยังไม่ได้รันทดสอบใด ๆ ตามคำขอของเจ้าของโปรเจกต์ (OWNER QA REQUIRED)**

วันที่ 20 ตุลาคม 2026 · `D:\etcstream`

## สถานะที่ต้องทราบก่อน

เพิ่มซอร์ส frontend, API, แบบจำลองฐานข้อมูล ตัวคำนวณอันดับ และหน้าผู้ดูแลแล้ว แต่ **ยังไม่ได้เปิดบริการออนไลน์หรือรัน migration** และยังไม่มี authoritative gameplay replay ที่ทำให้ผลเล่นปัจจุบันรับรองเป็น VERIFIED ได้ จึงยังไม่ควรเรียกว่าระบบแข่งขันจัดอันดับพร้อมใช้จริง

ไม่มีผู้เล่น คะแนน สหาย ฤดูกาล คู่แข่ง หรือผลการแข่งขันจำลอง ไม่มีการตั้งผลจากเบราว์เซอร์ให้เป็น VERIFIED เพื่อให้หน้าจอมีข้อมูล

## 1. สถาปัตยกรรมที่นำมาใช้

ต่อยอดบริการ Next.js Node และ SQLite ฝั่งเซิร์ฟเวอร์เดิม รักษา player ID, session, รหัสสหาย และประวัติเดิม ไม่มีฐานข้อมูลคู่ขนาน ไม่มีการใช้ localStorage/Zustand เป็นแหล่งอ้างอิงคะแนนหรือความสัมพันธ์ผู้เล่น

การออนไลน์หลายเครื่องต้องมีหนึ่งโฮสต์ที่ทุกเครื่องเข้าถึงได้ พร้อมฐาน SQLite ถาวรชุดเดียว นี่เป็นทางติดตั้งเซิร์ฟเวอร์เดียว ไม่ใช่ระบบหลาย instance/หลายภูมิภาค งานนี้ไม่ได้เพิ่ม PostgreSQL เพราะมี backend กลางที่ใช้ต่อได้อยู่แล้ว และการย้าย auth/data-access ทั้งระบบโดยไม่มีการทดสอบจะกระทบประวัติเดิมมากกว่า ไม่เพิ่ม dependency หรือบริการเสียเงิน

## 2. ส่วนที่เขียนโค้ดแล้ว

### ผู้เล่นและความเป็นส่วนตัว

- ใช้ตัวตนสุ่มถาวรและเซสชัน HttpOnly เดิม ชื่อเล่นเป็นชื่อแสดงผล ไม่ใช่สิทธิ์เข้าบัญชี
- เพิ่มความยินยอม `rank_public` แยกจากการแสดงรายชื่อและ presence ค่าเริ่มต้นปิด ผู้เล่นเก่าไม่ถูกนำเข้าแรงก์อัตโนมัติ
- ต้องเปิดรายชื่อและยินยอมเข้าทำเนียบ จึงอยู่ในกลุ่มสาธารณะที่คิดอันดับ/แต้ม การปิดสิทธิ์ยังเก็บประวัติส่วนตัวไว้
- รหัสกู้คืนสุ่ม 32 bytes เก็บ hash ใช้ครั้งเดียวใน 30 วัน สร้างใหม่แทนรหัสเก่า คืนตัวตนโดยยกเลิกเซสชันเดิม ไม่รับสิทธิ์จากชื่อเล่นหรือรหัสสหาย
- เพิ่ม UI กู้คืนและออกจากตัวตนพร้อมคำเตือน ไม่มีการรวมสองตัวตนเงียบ ๆ

### รอบแข่งขันและความจริงของผล

- เพิ่ม request ID สำหรับสร้างรอบซ้ำอย่างปลอดภัย การ retry คำขอเดิมไม่สร้างรอบใหม่หรือคิดแต้มเพิ่ม
- ใช้เวลาเริ่ม นับถอยหลัง บทลงโทษ และการจบรอบจากเซิร์ฟเวอร์เดิม
- ตรวจ idempotency ของลำดับเหตุการณ์ หากเลขเดิมแต่ชนิดเหตุการณ์ไม่ตรงจะปฏิเสธ
- โหลดเลขเหตุการณ์ล่าสุดกลับเมื่อเปิดรอบเดิม ลดการส่งเลขเริ่มใหม่ผิดชุด
- รอบ RUNNING ที่เกิน 4 ชั่วโมงถูกเปลี่ยนเป็น DNF เมื่อมีคำสั่งรอบถัดไป ไม่รับผลหมดเวลาเป็นคะแนน
- เพิ่มคิวตรวจและสถานะปฏิเสธพร้อม audit ผู้ดูแลเห็นผลรอตรวจเก่าด้วย โดยไม่เปลี่ยนผลเก่าเป็นหลักฐานใหม่
- การส่งปัจจุบันยังเป็น UNDER_REVIEW แม้ตรวจการต่อสัญญาณจากข้อมูลที่ส่งมาได้ ไม่มีกลไกเลื่อนเป็น VERIFIED โดยไม่มีหลักฐาน

### ทำเนียบรายด่าน

- คำนวณฝั่งเซิร์ฟเวอร์จากผลดีที่สุดของแต่ละผู้เล่น แยก 25 ด่านและเวอร์ชันกติกา
- รับเฉพาะ VERIFIED ที่ไม่ invalid มี `verified_at`, `validation_version`, เวลารวมตรงกับเวลาจริงบวกบทลงโทษ
- เวลารวมน้อยก่อน แล้วบทลงโทษ เวลาจริง เวลารับรอง และรหัสผล ไม่ปนผลจาก Level 1 กับ Level 5
- ขอบเขตทั้งหมด สหายรวมตัวเอง และหน้าต่างรอบอันดับตัวเอง ±3 คำนวณด้วย SQL ฝั่งเซิร์ฟเวอร์
- แสดงอันดับทั้งหมดแยกจากอันดับกลุ่มสหาย ใช้ความสัมพันธ์ accepted และนโยบายปิดกั้นจริง
- มี `hasMore/nextOffset` และแบ่งหน้า 25 รายการ ไม่วาง pager สมมติเมื่อไม่มีหน้าเพิ่ม
- แถบอันดับของฉันคงอยู่แม้ไม่ติดหน้าแรก แยก best กับ latest และบอกว่าไม่มีอันดับเมื่อไม่ได้ยืนยันหรือไม่ยินยอมเปิดเผย
- รองรับกรองกติกาปัจจุบัน ทุกเวลา 7 วันล่าสุด และฤดูกาลที่มีจริง

### แรงก์ฤดูกาล

- เพิ่ม `/arena/ranked` และเมนูในแถบเดียวกับ V5
- ฤดูกาลมีชื่อ เวลา สถานะ เวอร์ชันการคิดคะแนน และรายการเวอร์ชันของ 25 ด่านที่ตรึงตอนสร้าง
- คะแนนรายด่าน round(1000 × (N−r+1) / N) จาก best VERIFIED ของคนละผู้เล่น รวมเฉพาะ 5 ด่านต่างกันที่ได้แต้มสูงที่สุด สูงสุด 5000 คะแนน ผลซ้ำไม่สะสม
- คะแนนเท่ากันใช้จำนวนด่านยืนยันมากกว่า เวลาที่ได้ชุดผลก่อน และ immutable player ID ตามกติกา V1
- ชั้นแรงก์ 6 ชั้นใช้เกณฑ์จากไฟล์กติกา ไม่คาดเดาจากชื่อ การเปิดหน้า หรือรอบฝึกทั่วไป
- แสดงอันดับชั่วคราวเมื่อจำนวนผู้เล่น/จำนวนด่านยังน้อย รวมกรณีด่านที่มีผู้เข้าเกณฑ์น้อย
- คำนวณจากฐานจริงระหว่างฤดูกาลโดยตรง ไม่มี client score หรือ materialized cache ที่แยกจากแหล่งจริง
- ปิดฤดูกาลได้หลัง cutoff เท่านั้น บันทึกทั้งอันดับฤดูกาล อันดับรายด่าน และผลอ้างอิงใน transaction เดียว พร้อม trigger ป้องกันแก้ snapshot/กติกาเดิม
- เมื่อยกเลิกหลักฐานหรือถอนสิทธิ์แสดงผล รายการไม่เข้าเกณฑ์อาจถูกถอนจากหน้าประวัติสาธารณะ แต่ไม่ rescore/เลื่อนอันดับที่บันทึกของผู้อื่นย้อนหลัง

### สหาย การเชื่อมต่อ และหน้าตา

- สหายแสดงชั้น/คะแนนจริงที่เปิดเผย และมีส่วนเปรียบเทียบ best รายด่านระหว่างตัวเองกับสหายที่อนุญาต
- หน้าแรกมีสัญญาณสหายออนไลน์จาก lease จริงที่ยังสดและยินยอม ไม่ใช้จำนวนบัญชีทั้งหมดแทน
- แสดงสถานะเชื่อมต่อ/กำลังโหลด/ข้อมูลเดิม/ผิดพลาด และ retry แยกจากข้อมูลว่าง
- หน้าอันดับ polling ราว 20 วินาที เฉพาะหน้าที่มองเห็น ถ้าเชื่อมต่อผิดพลาดจะถอยระยะสูงสุด 120 วินาทีและยกเลิก request เมื่อออก
- Presence เดิม heartbeat ราว 30 วินาทีและหมดความสด 90 วินาที ไม่มีการเพิ่ม WebSocket/SSE หรืออ้างว่ามี live opponent
- คงภาพ V5 และโทนเซียนจีน เพิ่มป้ายแรงก์ แผงอันดับที่ตรึง รายการฤดูกาล และทางวิถีกระบี่ ไม่มีการเปลี่ยนฉาก 3D ให้เป็นเครื่องมือแฟนตาซีที่ผิดความจริง

### ผู้ดูแล

- `/admin` ยังเป็นทางเข้าสิทธิ์เดียว เมนูสาธารณะไม่ให้สิทธิ์จากชื่อ “แอดมิน”
- เพิ่ม `/admin/seasons` สร้าง/กำหนดเวลา เปิด ปิด snapshot เก็บประวัติ และคำนวณสถานะฤดูกาลปัจจุบัน
- เพิ่ม `/admin/reviews` ดูคิวและปฏิเสธผลพร้อมเหตุผล ไม่มีปุ่มรับรองข้อมูลเบราว์เซอร์ให้เป็นคะแนนทางลัด
- คำสั่งสำคัญต้องระบุเหตุผลและพิมพ์รหัสเป้าหมาย/CREATE ยืนยัน มี audit เดิมรองรับ
- เพิ่มตัวเลขจริงในภาพรวม ได้แก่ ผู้ยินยอมออนไลน์ ผู้มีสิทธิ์เข้าทำเนียบ ผลที่มีข้อมูลรับรอง และฤดูกาลเปิด แสดงไม่พร้อมเมื่อ schema ยังไม่เพิ่ม
- เครื่องมือดูแลชื่อ ล้างชื่อ ซ่อน ระงับ คืนสิทธิ์ ทำให้ไม่ระบุตัวตน ยกเลิก/คืนผล และ Mission Hall เดิมยังอยู่

## 3. ต้องให้เจ้าของตั้งค่าก่อน

1. อ่านและอนุมัติ `server/arena/migrations/002-online-ranked.sql` พร้อมสำรองฐานข้อมูลจริง
2. ใช้ตัวรัน `scripts/migrate-arena-v6.mjs` ด้วยตนเองตามคู่มือ ไม่มีการเรียก migration ตอนแอปเริ่ม
3. ตั้ง `ARENA_DB_PATH`, `ARENA_PUBLIC_ORIGIN` ในโฮสต์ที่มี Node/SQLite และพื้นที่ถาวร
4. จัด HTTPS และให้สองเครื่องเข้าที่ origin เดียวกัน `localhost` คนละเครื่องไม่ได้เชื่อมถึงกันเอง
5. ผู้ดูแลสร้างฤดูกาลจริงและผู้เล่นยินยอมเข้าทำเนียบตามต้องการ ไม่ได้สร้างฤดูกาลตัวอย่างให้

คู่มือเต็ม: `docs/online-arena/ARENA_ONLINE_DEPLOY_TH.md`

## 4. ยังบล็อก / ยังไม่ได้ทำ

- **ตัวรับรองการแข่งขันแบบตรวจย้อนกลับการกระทำทั้งหมด:** ยังไม่ได้ทำ จึงไม่มีทาง gameplay ปัจจุบันที่ออก VERIFIED และให้คะแนนฤดูกาลได้อย่างเชื่อถือได้ นี่เป็นข้อจำกัดหลัก ไม่ได้อ้างว่า schema และหน้าแรงก์ทำให้ส่วนนี้เสร็จแล้ว
- **Duel แบบสองผู้เล่นจริง:** ยังปิด ไม่ทำห้องจำลอง ไม่ประกาศผู้ชนะจาก client
- **Deployment:** ยังไม่ดำเนินการ ไม่ทราบว่าโฮสต์จริงรองรับ storage ถาวร/`node:sqlite` หรือไม่ ยังไม่มีหลักฐานสองเครื่องเชื่อมจริง
- **หลาย app instances / PostgreSQL:** ไม่ได้ทำ ต้องมี data-layer migration และแผนย้ายข้อมูลเดิมก่อนขยาย
- **WebSocket/SSE:** ไม่ได้ทำ ใช้ visibility-aware polling เท่านั้น
- **ส่วนต่างแต้มก่อน/หลังแต่ละรอบและกราฟแต้มย้อนหลัง:** ยังไม่มีบันทึก จึงไม่สร้างข้อมูลหรือเปอร์เซ็นต์พัฒนาการขึ้นมาแทน
- **ประวัติ session/device เต็มรูปแบบและการผูกหลายเครื่องพร้อมกัน:** ไม่ได้ทำ UI รหัสกู้คืนเป็นการย้ายสิทธิ์โดย revoke เครื่องเก่า
- **โหลดสูง การกู้ backup และการตรวจความปลอดภัยขณะทำงาน:** ยังไม่ได้ทดสอบ

## 6. ไฟล์เดิมที่แก้รอบ V6

- `.gitignore` — ยกเว้นเฉพาะ `.env.example` ที่ไม่มีค่า ขณะที่ `.env.local` และไฟล์ลับยังถูก ignore
- `SECURITY.md` — บันทึกขอบเขตความเชื่อถือ กติกาความยินยอม รหัสกู้คืน และข้อจำกัดการติดตั้ง V6 โดยไม่อ้างว่าผ่านตรวจขณะทำงาน
- `server/arena/db.ts` — ตรวจความพร้อม schema V6 โดยไม่รัน migration
- `server/arena/auth.ts` — production ต้องมี canonical HTTPS origin ก่อนรับ mutation
- `server/arena/service.ts` — ความยินยอม rank, metadata ผล, ชนิดเหตุการณ์ซ้ำ และ timeout โดยคงผลจากเบราว์เซอร์ไม่จัดอันดับ
- `app/api/arena/[...path]/route.ts` — endpoint อันดับ/ส่วนตัว/สหาย/ฤดูกาล/กู้คืน/คิวผล เชื่อมระบบเดิม
- `app/api/admin/[...path]/route.ts` — ฤดูกาล รีวิว ภาพรวม และการตรึงกติกาขณะมีฤดูกาลเปิด
- `components/arena/client-api.ts` — สัญญาข้อมูลใหม่และข้อความเครือข่ายภาษาไทย
- `components/arena/shell.tsx` — เมนู Ranked และข้อมูลเชื่อมต่อ/ชั้นแรงก์จริง

ไฟล์เหล่านี้หลายโฟลเดอร์เป็น untracked อยู่ก่อน V6 รายการ Git ของทั้งโครงการยังมีงานเก่าจำนวนมาก ไม่ได้ล้าง ย้อน หรือถือเป็นงานใหม่ทั้งหมด

## 7. สิ่งที่ไม่ได้รันและสิ่งที่คงไว้

ไม่ได้รัน tests, lint, typecheck, build, browser automation, เล่นเกม, auto-solver, screenshot QA, migration, seed, deploy, commit หรือ push ไม่แก้ `.env.local` และไม่อ่านหรือพิมพ์ค่าลับ

อ่านทบทวนเฉพาะเอกสารและซอร์สที่เกี่ยวข้องกับการแก้ รวมสถานะ Git เท่านั้น ไม่ใช้คำว่า PASS และไม่ใช้ผลตรวจ V5 หรือรุ่นก่อนรับรอง V6

Welcome, Academy, ห้องฝึกอิสระ, ฉากและตัวตรวจ 25 ภารกิจ, สาย/พอร์ต/อุปกรณ์จริง, กระเป๋า, การควบคุม และข้อมูลความก้าวหน้าเดิมไม่ได้ถูกออกแบบให้เปลี่ยนหรือถูกถอดออกในงานนี้ แต่การถดถอยระหว่างทำงานยังต้องให้เจ้าของตรวจด้วยตนเอง

## 8. รายการแนะนำให้เจ้าของตรวจเอง

รายการนี้ **ยังไม่ได้ดำเนินการ**:

- [ ] สำรองและเพิ่ม schema ในฐานที่เลือกอย่างถูกต้อง โดยไม่สูญเสียผู้เล่น/ประวัติเดิม
- [ ] สองอุปกรณ์จริงใช้ HTTPS origin เดียวกัน ได้ตัวตนแยกกัน และชื่อซ้ำไม่รับสิทธิ์ผู้เล่นเดิม
- [ ] สหาย ส่ง/รับคำขอ เปรียบเทียบ ปิดกั้น และเปิด/ปิดความยินยอมได้ตามสิทธิ์
- [ ] รหัสกู้คืนใช้ครั้งเดียว หมดอายุได้ และไม่รั่วใน public DTO/log พร้อมยกเลิก session เดิมตามนโยบาย
- [ ] รอบ retry ไม่ซ้ำ ลำดับเหตุการณ์ไม่ข้าม เวลา/บทลงโทษ/สถานะรอตรวจและ DNF ถูกต้อง
- [ ] ทุกหน้าทำเนียบแยกด่าน กติกา ช่วงเวลา สหาย รอบตัวฉัน และ best/latest อย่างชัดเจน
- [ ] เมื่อมี authoritative validator ที่ตรวจรับแล้วในอนาคต ตรวจผลจริงเข้าสู่อันดับและสูตรคะแนน ห้ามใส่ VERIFIED ปลอมแล้วถือว่าได้ทดสอบการแข่งขันจริง
- [ ] สร้าง/เปิด/สิ้นสุด/ปิด/เก็บฤดูกาลและ snapshot คงที่ Audit ครบ และไม่มีแต้มจากผลรอตรวจ/ยุติ/ปฏิเสธ
- [ ] ตรวจสิทธิ์ผู้ดูแลด้วยบัญชีจริง คำขอต่าง origin เครือข่ายหลุด การอัปเดตข้ามเครื่อง หน้าจอแคบ และระบบเกมเดิม
